# 首批来源与接入验证

精选来源是内容提供者，RSS/API/网页/搜索是获取方式。第一版同时支持多个来源，通过适配器输出统一文章记录。

## 候选来源池

以下均为待验证清单；不假定每个站点提供原生 RSS，也不将搜索发现的 URL 直接当作已验证的稳定接口。

| 来源 | 范围 | 优先接入方式 | 优先级 |
| --- | --- | --- | --- |
| OpenAI 官方发布 | 模型、开发者产品、研究 | 原生 RSS 或发布页 | 高 |
| Anthropic News | 模型、开发工具、研究 | 发布页；验证是否有官方 feed | 高 |
| Google DeepMind 官方博客 | 模型、重大研究 | 原生 RSS 或发布页 | 高 |
| Qwen 官方渠道 | 模型、开源发布 | 官方博客与仓库，核实账号归属 | 高 |
| DeepSeek 官方渠道 | 模型与开源发布 | 官方站点与仓库，核实账号归属 | 高 |
| Hugging Face Blog | 开源生态、工具、技术文章 | RSS 候选 `/blog/feed.xml`，需实测 | 中 |
| vLLM、Transformers、llama.cpp | 重要版本与功能 | 指定仓库 GitHub Releases API | 中 |
| arXiv 相关分类与关键词 | AI 研究线索 | API/RSS，过滤并遵守限流 | 中 |
| Hacker News | 开发者热点 | 官方 API，结合讨论增长与主题过滤 | 中 |
| 机器之心、量子位 | 中文热点 | 公开网页或公众号桥接 | 中 |

首轮优先跑通 5 个不同类型来源，再扩充到约 10～15 个逻辑来源。仓库的每个补丁版本不自动成为新闻。

## 搜索

搜索承担定时补漏和重大事件追溯原始来源。初始可每小时补漏一次，核验按事件触发，设置每日调用预算与单事件调用上限。提供商待选，不绑定特定品牌。

搜索索引时间不等于事件时间；结果摘要只用于发现，原文或可引用证据才用于成稿。搜索暂时失败不阻断已经具备充分一手证据的消息。

## 微信公众号

候选方案：独立运行 WeRSS/we-mp-rss，将文章转为 RSS 或调用标准接入接口。采集服务自行维护所需登录状态，AInxiety 只消费结果。

先选 2～3 个目标公众号验证更新延迟、正文完整度、链接稳定性、登录维护和失败表现。不承诺任意公众号实时可用；保留手动提交链接入口。桥接异常时标记来源降级，不把“没有采集成功”解释成“没有新闻”。

## 每个来源的配置

`source_id`、名称、站点/账号归属、接入类型、入口地址、主题、语言、来源类别（一手/媒体/社区）、可信度依据、检查间隔、限流策略、启停状态。

运行状态包含最近尝试/成功时间、游标、ETag/Last-Modified（如支持）、失败次数、退避截止时间、最近文章时间。凭据存储为秘密配置引用，不放进源码或普通日志。

首次接入只抓取有限时间窗口；历史回填默认不触发快讯。尊重来源限制，使用超时、条件请求、退避和缓存。

## 接入完成条件

- 确认来源归属和真实入口，记录验证日期。
- 成功解析标题、稳定链接、可用正文及时间状态。
- 验证重复拉取、正文更新、空 feed、分页和限流行为。
- 记录一个采集失败案例及恢复方式。
- 观察更新延迟后再设置轮询频率。
